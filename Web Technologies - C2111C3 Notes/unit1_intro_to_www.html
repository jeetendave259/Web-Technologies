01Concept of the World Wide Web

The World Wide Web (WWW, or Web) is an information system of interlinked resources that people access over the Internet. A web resource may be a page, image, video, downloadable file, or data service. Hyperlinks connect resources so users can move from one to another.

The Web is built on open technologies. A browser asks for a resource using its address (usually a URL), communicates with a web server using HTTP or HTTPS, and renders the returned content. HTML describes document structure; CSS controls presentation; JavaScript can add behavior. The World Wide Web Consortium (W3C) and other standards organizations publish specifications that help browsers and sites interoperate.

Resources

Pages and other content are identified by addresses and may be hosted on different servers.

Hyperlinks

Links connect documents and data, making it possible to navigate between resources.

Open standards

Common protocols and formats let browsers, servers, and tools from different vendors work together.

URL anatomy

Consider https://www.example.com:443/guide/http?level=1#request:

PartExampleMeaning
SchemehttpsHow the browser communicates; HTTPS uses HTTP protected by TLS.
Hostwww.example.comThe domain name resolved through DNS to an IP address.
Port443The server endpoint; HTTPS commonly uses 443, HTTP commonly 80.
Path/guide/httpIdentifies a resource or route on the host.

History: Tim Berners-Lee proposed the Web at CERN in 1989 to help researchers share information. The first website described the project itself. The Web has since grown from mostly read-only pages into interactive applications and services.

02Internet and WWW

The Internet is the global network of interconnected networks: hardware, links, routers, addressing, and protocols that move data between devices. The Web is one service that uses this network. Email, online games, file transfer, and voice calls can also use the Internet without being Web pages.

Internet: the infrastructure

IP addressing and routing deliver packets between networks. Transport protocols such as TCP or QUIC carry application traffic across connections.

Web: an application on it

Browsers use URLs, HTTP, HTML, and related technologies to request and display linked resources.

Analogy: The Internet is the road system; the Web is one kind of journey made using those roads. The roads carry many other kinds of traffic too.

From domain name to web page

  1. The browser parses a URL and checks its cache and local configuration.
  2. DNS resolves the host name to an IP address.
  3. The browser establishes a connection to the server (and negotiates TLS for HTTPS).
  4. It sends an HTTP request; the server returns an HTTP response.
  5. The browser parses HTML, requests referenced resources, and renders the page.
IP address basics: IPv4 addresses are 32 bits (for example, 192.0.2.10); IPv6 addresses are 128 bits (for example, 2001:db8::10). Examples in these documentation ranges are reserved for teaching and should not be used as live server addresses.

03HTTP Protocol: Request and Response

HTTP (Hypertext Transfer Protocol) is a stateless application-layer protocol used to exchange requests and responses. A request identifies a method and target and may include headers and a body. A response includes a status code, headers, and an optional body. Cookies or application tokens can be used to associate multiple requests with a session.

Example request

GET /api/message?name=Asha HTTP/1.1
Host: localhost:8080
Accept: application/json
User-Agent: ExampleBrowser/1.0

Example response

HTTP/1.1 200 OK
Content-Type: application/json; charset=utf-8
Cache-Control: no-store

{"message":"Hello, Asha!","source":"server"}
Request / response partWhat it tells the other sideExamples
Request lineMethod, resource target, and protocol version.GET /docs HTTP/1.1
Request headersMetadata about the host, accepted content, credentials, or client.Host, Accept, Content-Type
Request bodyOptional data sent to the server, often with POST or PUT.Form fields or JSON
Status lineProtocol version and outcome code.200 OK, 404 Not Found
Response headersMetadata about the result and how it should be handled or cached.Content-Type, Cache-Control
Response bodyThe returned representation, such as HTML, JSON, an image, or no body.HTML or API data

Common methods and status codes

  • GET retrieves a representation; POST submits data; PUT replaces a resource; DELETE requests deletion.
  • 200 means success; 201 means created; 301/302 indicate redirects; 400 is a bad request; 401 is unauthenticated; 403 is forbidden; 404 is not found; 500 is a server error.
  • HTTPS protects HTTP traffic in transit with TLS. It does not by itself prove that a site is trustworthy or that its content is safe.

Run a real local HTTP request and response

The following browser demo calls a local Node.js server and displays the actual HTTP status, response content type, and returned JSON. To run it, save the server code below as server.mjs beside this HTML file, install Node.js if needed, run node server.mjs, and open http://localhost:8080. The API and page are same-origin and remain on your own computer.

Start the local server and submit the form to send a real HTTP request.

Request: GET /api/message?name=Asha Response: not sent yet

Runnable server: server.mjs

import { createServer } from "node:http";
import { readFile } from "node:fs/promises";
import { fileURLToPath } from "node:url";

const pagePath = fileURLToPath(new URL("./unit1_intro_to_www.html", import.meta.url));
const server = createServer(async (request, response) => {
    const url = new URL(request.url ?? "/", `http://${request.headers.host ?? "localhost"}`);

    if (request.method === "GET" && url.pathname === "/api/message") {
        const suppliedName = (url.searchParams.get("name") ?? "visitor").trim();
        const name = suppliedName.slice(0, 60) || "visitor";
        response.writeHead(200, {
            "Content-Type": "application/json; charset=utf-8",
            "Cache-Control": "no-store"
        });
        response.end(JSON.stringify({ message: `Hello, ${name}!`, source: "server" }));
        return;
    }

    if (request.method === "GET" && (url.pathname === "/" || url.pathname === "/unit1_intro_to_www.html")) {
        try {
            const page = await readFile(pagePath);
            response.writeHead(200, { "Content-Type": "text/html; charset=utf-8" });
            response.end(page);
        } catch (error) {
            console.error("Could not read the study-guide page:", error);
            response.writeHead(500, { "Content-Type": "text/plain; charset=utf-8" });
            response.end("The study-guide file could not be read.");
        }
        return;
    }

    response.writeHead(404, { "Content-Type": "text/plain; charset=utf-8" });
    response.end("Not found");
});

server.listen(8080, "127.0.0.1", () => {
    console.log("Open http://localhost:8080");
});

You can also inspect an HTTP exchange from a terminal while the server is running:

curl -i "http://localhost:8080/api/message?name=Asha"

04Web Browsers and Web Servers

A web browser is a client application that requests resources and presents them to a user. A web server is software that listens for requests and returns responses. “Server” can also refer to the computer or virtual machine running that software.

Browser (client)Web server
Resolves a URL and requests resources.Listens on a network address and receives requests, commonly on ports 80 (HTTP) or 443 (HTTPS).
Parses HTML into a document tree and CSS into style rules.Checks routing and access rules; locates a static file or passes work to an application.
Lays out and paints the page; runs client-side JavaScript in a browser environment.Returns static files or generated responses from application code and data services.
Examples: Firefox, Chrome, Safari, Edge.Examples: Apache HTTP Server, Nginx, Caddy, Microsoft IIS.

A browser rendering engine (such as Gecko, Blink, or WebKit) displays the page; a JavaScript engine executes scripts. A server such as Apache or Nginx handles HTTP connections and often works with application runtimes such as PHP, Python, or Node.js.

Static and dynamic responses: A static server can return a stored HTML file. A dynamic application can use request data, rules, or a database to create a different response for each request. Even a dynamic page is ultimately delivered as a response for the browser to render.

05Features of Web 2.0

Web 2.0 describes a shift toward participatory, interactive web services rather than pages that only publish information for reading. It is a broad term for a change in how people use the Web, not a new HTTP version or a formal technical standard.

User-generated content

People publish posts, photos, reviews, videos, and comments instead of only consuming material created by a site owner.

Social collaboration

Communities share, tag, discuss, and collaboratively edit material in social networks, blogs, forums, and wikis.

Rich interaction

JavaScript and asynchronous requests can update part of a page without a full reload. AJAX is a technique, not one specific format.

APIs and hosted services

HTTP APIs (often using JSON) let applications exchange data. Software as a Service runs software on hosted infrastructure and exposes it through the Web.

06Setting Up Unix and Linux Web Servers

A Unix-like web server needs a machine, a web-server program, a document root or application, network access, and safe configuration. The steps below show a small Apache virtual host on Debian or Ubuntu Linux. Commands and service names vary on other Unix-like systems; Fedora/RHEL and Nginx notes follow.

Apache on Debian or Ubuntu

Install Apache, create a document root, and create a tiny page. Commands using sudo change system configuration; review each path before running them.

sudo apt update
sudo apt install apache2
sudo systemctl enable --now apache2

sudo install -d -o "$USER" -g www-data -m 2750 /var/www/unit1-demo
cat > index.html <<'HTML'
<!doctype html>
<html lang="en">
<meta charset="utf-8">
<meta name="viewport" content="width=device-width, initial-scale=1">
<title>My first hosted page</title>
<h1>Hello from Apache</h1>
<p>This HTML file is being served over HTTP.</p>
</html>
HTML
sudo install -o "$USER" -g www-data -m 0640 index.html /var/www/unit1-demo/index.html

Create /etc/apache2/sites-available/unit1-demo.conf with this virtual-host configuration:

<VirtualHost *:80>
    ServerName unit1-demo.test
    DocumentRoot /var/www/unit1-demo

    <Directory /var/www/unit1-demo>
        Options -Indexes
        AllowOverride None
        Require all granted
    </Directory>

    ErrorLog ${APACHE_LOG_DIR}/unit1-demo-error.log
    CustomLog ${APACHE_LOG_DIR}/unit1-demo-access.log combined
</VirtualHost>

Enable and test the site. The reserved .test name is for testing; send the host header explicitly so Apache selects this virtual host.

sudo a2ensite unit1-demo.conf
sudo apache2ctl configtest
sudo systemctl reload apache2
curl -i -H 'Host: unit1-demo.test' http://127.0.0.1/

Firewall and public hosting

For a local-only lab, test on the server itself first. If you deliberately host a public site, configure the machine and network firewall for the required ports, use a real domain, configure HTTPS, update software, restrict file permissions, and monitor logs. Opening a port or forwarding traffic through a home router exposes the service to the Internet; do not expose an unpatched development server or private files.

On Ubuntu with UFW, a basic HTTP firewall rule is sudo ufw allow 80/tcp. Only allow HTTPS after TLS is configured. If deploying a public domain, use a trusted certificate authority and keep certificate renewal working.

Other Unix/Linux options

  • Fedora/RHEL with Apache: install httpd with sudo dnf install httpd, start it with sudo systemctl enable --now httpd, and use the distribution's firewall and SELinux guidance. The service and configuration paths can differ from Debian.
  • Nginx on Ubuntu: install with sudo apt install nginx; server blocks are commonly stored in /etc/nginx/sites-available/ and linked into sites-enabled/. Run sudo nginx -t before reloading with sudo systemctl reload nginx.
  • macOS / BSD / other Unix: package managers, service control, firewall tooling, and default paths differ. Follow the system's current Apache or Nginx documentation instead of assuming Ubuntu commands apply unchanged.

07Dynamic IP Addresses and Dynamic DNS

An IP address identifies a network interface for packet routing. A dynamic IP address is assigned for a period (a lease) by a DHCP server. Home routers typically receive a public-facing address from an ISP and separately assign private addresses to devices on the local network. The public address may change when the lease is renewed or the connection changes; the exact policy depends on the provider.

Public address

The Internet-facing address used by the router or host. Some ISPs use carrier-grade NAT, so a subscriber may not have a directly reachable public IPv4 address.

Private address

An internal address such as 192.168.1.20 used within a local network. It is not, by itself, a public destination on the Internet.

Dynamic DNS (DDNS)

A client updates a DNS record when the public address changes, so a hostname can continue to resolve to the latest address.

Why DDNS helps: A DNS name normally points to an address using records such as A (IPv4) or AAAA (IPv6). If a home-hosted server's public address changes, a DDNS client can authenticate to its provider and update the record. DNS caches may retain the old answer until the record's TTL expires. DDNS does not create a public IP, bypass carrier-grade NAT, open firewall ports, or make an unsafe server secure.

08Effective Web Design and Common Issues

Effective web design helps people accomplish their goals. It brings together useful content, clear interaction, accessible presentation, responsive layout, and reliable performance. Design decisions should be tested with real content and users, not based only on appearance.

User-centered hierarchy

Make the page purpose clear. Use meaningful headings, readable type, spacing, and contrast to guide attention to important information.

Navigation

Use descriptive link labels, consistent menus, a logical information structure, and visible feedback. Avoid trapping visitors in unclear or excessively deep paths.

Responsive design

Use flexible layouts and media queries so content works on narrow and wide viewports without horizontal scrolling or tiny text.

Accessibility

Use semantic HTML, keyboard-operable controls, visible focus, labels, alternative text for meaningful images, and sufficient color contrast.

Performance

Resize and compress images, minimize unnecessary assets, cache suitable resources, and avoid blocking the first render with needless scripts.

Compatibility and safety

Test across browsers and devices; keep software updated, use HTTPS, validate input, and protect personal data.

Common design issues and their remedies

IssueWhy it mattersBetter approach
Clutter and weak hierarchyPeople cannot tell what is important or where to begin.Group related content, prioritize one main action, and use whitespace intentionally.
Mobile unresponsivenessText and controls become difficult to read or use on small screens.Start with a flexible layout, test narrow viewports, and avoid fixed-width page containers.
Low contrast and inaccessible controlsSome people cannot perceive or operate content.Test text contrast; provide keyboard access, labels, and visible focus. WCAG 2.1's typical minimum for normal text is a 4.5:1 contrast ratio.
Slow loading and layout shiftsVisitors wait longer and controls can move while a page loads.Optimize media, specify image dimensions, defer nonessential code, and measure performance.
Broken links or browser-specific behaviorUsers lose trust or cannot complete tasks.Test links and key flows in multiple browsers; use standards-based HTML and CSS.
Security and privacy oversightsInput flaws or excessive data collection can expose users and systems.Validate on the server, encode output for its context, use least privilege, and collect only necessary information.

Unit 1 at a glance

  1. The Internet connects networks; the Web is a linked information system that uses the Internet.
  2. DNS helps resolve domain names; HTTP carries requests and responses between clients and servers.
  3. Browsers render resources, while web servers receive requests and return static or generated responses.
  4. Web 2.0 emphasizes participation, user-generated content, collaboration, and interactive services.
  5. Linux hosting requires careful server configuration, network access, permissions, and security maintenance.
  6. DDNS can keep a name updated when an eligible public IP changes, but it does not solve NAT or security issues.
  7. Effective design should be clear, responsive, accessible, fast, compatible, and safe.
