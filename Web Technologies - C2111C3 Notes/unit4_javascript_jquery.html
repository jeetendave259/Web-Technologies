01Client-Side Scripting with JavaScript

JavaScript runs in the browser and responds to user actions. It can calculate values, choose what happens next, and update the current page without rebuilding its HTML by hand. In a web application, JavaScript is what turns a static page into an interactive interface: it validates entries, changes text, reveals tabs, adds animations, and fetches new data from a server.

According to the MDN JavaScript introduction, JavaScript is a high-level, dynamic scripting language that can be used to control the behavior of a web page. It is not the same as HTML or CSS: HTML gives structure, CSS gives presentation, and JavaScript gives behavior. It is one of the core technologies of the web and is run by every modern browser.

At the core of JavaScript are a few fundamental ideas. Variables store information, conditions let the program make decisions, loops repeat tasks, and functions package reusable logic. These concepts are the building blocks of every event-driven interaction in web development. For example, a course portal may use a variable to hold the selected unit, an if statement to decide which content to display, and a function to update the page when a student clicks a button.

JavaScript building blocks: values, variables, operators, expressions, control flow, functions, objects, arrays, and the browser APIs such as document and window.

Variables and values

Use const for bindings that will not be reassigned and let when reassignment is needed. Values can be strings, numbers, booleans, arrays, objects, or null.

Conditions

if, else if, and else choose a branch based on a true-or-false expression. They are used for testing validity, checking selections, and controlling the flow of a program.

Loops

for and while repeat work. Use for...of to visit each value in an iterable such as an array, which is common when printing lists, updating scores, or reading data.

Functions

Functions package reusable instructions. They can receive parameters and return a result, reducing repetition and making code easier to read and maintain.

JavaScript Data Types

A data type describes the kind of value a variable contains and the operations that make sense for it. JavaScript is dynamically typed: a variable can hold values of different types at different times, and you do not write a type declaration when creating it. Use typeof to inspect many values while learning or debugging.

02JavaScript Objects and the DOM

Objects group related data and behavior. The Document Object Model (DOM) represents an HTML document as a tree of nodes. JavaScript can find nodes, read or change their content, update attributes and classes, and create new elements. This is the heart of dynamic web pages: instead of static text, the browser script can modify a heading, change a button label, inject content into a list, or highlight a card after an action.

In MDN terms, an object is a collection of related properties and methods. For example, a student object can contain properties such as name, rollNo, and department, along with methods like displayInfo(). The DOM is a browser-created object model that exposes every HTML element as a JavaScript object. Because the DOM is a tree, JavaScript can traverse from a parent node to child nodes, update specific elements, and react to user events.

In real websites, the DOM is what lets the page respond to the user without reloading. A login form may check that the password field is valid, a shopping cart might update totals after a quantity change, and a dashboard may replace a chart when a user selects a different period. JavaScript uses object properties, method calls, and selector APIs to work with these elements.

const learner = {

03Forms and Validation

Form validation checks user input before an application accepts or sends it. HTML provides basic constraints such as required, type="email", and minlength; JavaScript can add application-specific checks and feedback. The purpose is not simply to block mistakes; it is to guide the user, reduce errors, and save server resources by stopping bad data before it is submitted.

Typical validation includes checking that a field is not empty, that a password is long enough, that the email format matches expected syntax, and that required values are selected. In browser-side validation, JavaScript can show custom error messages and highlight the wrong input, while HTML attributes provide quick built-in rules. The browser also supports validation APIs such as checkValidity(), validity, and setCustomValidity(), which let developers combine built-in rules with custom business logic. However, because a user can disable JavaScript or send data directly to a server, final checks must still happen on the server side as part of secure application design.

HTML Validation Rules

Start with HTML attributes whenever possible. They describe the expected input directly in the markup, work with browser and assistive-technology features, and reduce the amount of JavaScript needed. The browser checks these constraints when a form is submitted unless validation is disabled with the novalidate attribute.

AttributeExampleWhat it checks
required<input required>A value must be entered or selected.
type<input type="email">Uses an input suited to the data and checks basic formats such as email or URL.
minlength / maxlength<input minlength="2" maxlength="40">Sets allowed text length.
min / max / step<input type="number" min="1" max="10" step="1">Limits numeric or date values and permitted increments.
pattern<input pattern="[A-Z]{2}[0-9]{4}">Requires text to match a regular-expression pattern.

Validation Flow

  1. Collect the values when the user submits the form.
  2. Check basic constraints, such as required fields and valid input types.
  3. Apply any extra rules specific to the application, then explain how to correct errors.
  4. Only continue with submission when the values pass; validate them again on the server.

For custom checks, checkValidity() returns true when all constraints pass. reportValidity() asks the browser to display its validation feedback. The validity property gives details such as whether a value is missing or has the wrong format, and setCustomValidity(message) can add a custom error. Clear a custom error by calling setCustomValidity("") when the value becomes valid.

Important: Client-side validation improves feedback but is not a security boundary. A server must validate submitted data too.
form.addEventListener("submit", (event) => {
    event.preventDefault();

    if (!form.checkValidity()) {
        form.reportValidity();
        message.textContent = "Please correct the highlighted fields.";
        return;
    }

    message.textContent = "Form is ready to submit.";
});

This example prevents the default page reload so the script can check the fields first. In a real application, the valid branch would send the form data to a server; this page's demo only displays a confirmation message. Keep labels connected to inputs and make error feedback clear, as the demo does with a message announced through aria-live.

04DHTML: HTML, CSS, and JavaScript Together

DHTML, short for Dynamic HTML, is a descriptive term for using HTML, CSS, and JavaScript together to make a page respond to changes and user actions. It is not a separate programming language, browser feature, or software package. HTML supplies the elements and meaning, CSS controls their appearance, and JavaScript uses the DOM and browser events to update content or state while the page is open.

For example, an online learning page might use HTML to create a course card and a button, CSS to define the card's normal and highlighted appearances, and JavaScript to respond when the button is activated. JavaScript usually changes the DOM, often by adding or removing a CSS class; the browser then applies the matching CSS rules and redraws the affected part of the page. This targeted update can happen without rebuilding the document or reloading the whole page.

HTML: structure and meaning

Creates semantic elements such as headings, cards, forms, and buttons that users and assistive technologies can understand.

CSS: presentation

Defines layout, colors, spacing, and visual states. A class lets the same element have different styles without mixing style rules into JavaScript.

JavaScript: behavior

Listens for events, makes decisions, and updates DOM content, attributes, or classes in response.

How a DHTML Interaction Works

  1. The browser reads the HTML and creates a DOM tree of elements.
  2. The browser applies CSS rules to determine how those elements look.
  3. JavaScript finds the relevant elements and registers an event listener.
  4. When the event occurs, JavaScript updates the DOM; the browser applies the changed styles and renders the result.

05Events and Buttons

An event is something that happens in the browser, such as a click, key press, form submission, or page load. An event listener connects an event to a function. Prefer addEventListener() so behavior remains separate from HTML structure and several listeners can be attached without mixing logic into inline markup. This separation is a key principle of maintainable front-end code.

When a user interacts with the page, the browser creates an event object that contains useful information such as which element was clicked and what type of event occurred. Developers can inspect that object to decide how to respond. This is the foundation for features such as form validation, drag-and-drop interfaces, button-based actions, keyboard shortcuts, and interactive charts.

click

Button activation, including keyboard activation for native buttons.

input

Fires as a user edits an input value and is useful for real-time validation.

submit

Fires when a form is submitted; useful for validation and handling.

Event object

Provides details about the event and the element that received it, enabling targeted behavior.

06AJAX and Asynchronous Web Applications

AJAX stands for Asynchronous JavaScript and XML. The name comes from an earlier period of web development, when XML was a common response format. Today, AJAX describes the broader technique of sending an HTTP request from JavaScript and updating part of the page with the response, without loading a new document. JSON is common, but a response can also be text, HTML, XML, or another resource type.

This pattern is useful when only one part of a page needs new information: searching a catalog, refreshing messages, checking a username, or submitting a form. It can reduce unnecessary page reloads and data transfer. The browser still needs a server or API to provide real data; AJAX is the communication pattern, not a server or database by itself.

Request and Response Cycle

  1. A user action or another event starts a request to a server URL, often called an endpoint.
  2. The browser sends the request, usually with a method such as GET to retrieve data or POST to send data.
  3. The server returns a response containing a status and, when appropriate, a body such as JSON or text.
  4. JavaScript checks the response, reads the body, and updates the needed DOM elements.
  5. The rest of the document stays in place; the interface can show loading, success, or error feedback along the way.

What Asynchronous Means

A synchronous operation makes the next step wait for the current one to finish. A network request can take a noticeable amount of time, so browser APIs such as fetch() work asynchronously: they return a Promise representing work that will finish later. While the browser handles the network activity, JavaScript can continue responding to events and the page can remain interactive.

When the response arrives, the promise is fulfilled with a Response, or rejected for a network-level problem. The response body is read separately and asynchronously. An async function lets us write this sequence with await; await pauses that function until its promise settles, not the whole browser interface. Asynchronous does not mean that every JavaScript instruction runs in parallel.

Using Fetch and Handling Errors

fetch() is the modern browser API for HTTP requests. A successful call gives JavaScript a response object, but an HTTP error status such as 404 or 500 does not normally reject the fetch promise. Check response.ok before reading the body. Then use response.json() for JSON; it returns a promise too, and it can fail if the body is not valid JSON.

async function loadCourses() {
    status.textContent = "Loading courses...";

    try {
        const response = await fetch("/api/courses");
        if (!response.ok) {
            throw new Error(`HTTP error: ${response.status}`);
        }

        const courses = await response.json();
        output.textContent = courses.map((course) => course.name).join(", ");
        status.textContent = "Courses loaded.";
    } catch (error) {
        status.textContent = "Could not load courses. Check the connection and try again.";
        console.error(error);
    }
}

loadCourses();

In this example, /api/courses is a placeholder endpoint. It must exist and return JSON containing an array of course objects with a name property. The try...catch handles network errors, non-success HTTP statuses that we explicitly turn into errors, and problems reading or parsing the response body.

Cross-origin requests: A page can usually request resources from its own origin. If an API is hosted on a different origin, the server must allow the page through Cross-Origin Resource Sharing (CORS). This is a browser security rule; adding mode: "no-cors" is not a general fix because it produces an opaque response that JavaScript cannot read normally.

07Introduction to jQuery

jQuery is a JavaScript library that offers concise APIs for selecting elements, handling events, updating the DOM, effects, and AJAX. It was especially valuable when browser differences required extra compatibility work. Modern browsers provide many equivalent capabilities directly, but jQuery remains in existing projects and is useful to recognize because many older codebases still use it and many students need to read it when maintaining legacy websites.

The main advantage of jQuery is readability and shorter code. Instead of writing several DOM API calls, a developer can select an element with a CSS-style expression and change its content or classes in a single chained statement. It also simplified event-driven programming and AJAX by providing consistent behavior across browsers at a time when JavaScript support varied significantly.

Select elements

$(".notice") selects elements using familiar CSS selector syntax.

Wait for the DOM

$(function () { ... }) runs after the document is ready to be manipulated.

Handle events

.on("click", handler) attaches an event listener.

Update content

Methods such as .text(), .addClass(), and .toggleClass() manipulate selected elements.

Short Beginner-Friendly Summary

JavaScript is the language that makes a web page interactive. It helps us store data in variables, check conditions, repeat actions using loops, and reuse logic using functions. We can respond to user actions like clicks and form submissions through events, and we can change page content with the DOM. JavaScript is also used to validate forms, fetch data from a server, and build dynamic experiences in websites and applications.

For a beginner, the most important idea is this: HTML defines what is on the page, CSS decides how it looks, and JavaScript decides what happens when the user interacts with it. Once you understand this, most JavaScript topics become easier to learn.
