01Introduction to XML

XML (Extensible Markup Language) is a text-based markup language for representing, storing, and transporting structured data. Unlike HTML, which has a predefined set of tags for displaying a page, XML lets the author define descriptive tags that fit the data. XML describes what information means; another program or stylesheet decides how to use or display it.

For example, a course record can be represented as nested elements. The tag names—course, title, and credits—describe the values rather than their visual appearance. Because the document is plain text and has an explicit tree structure, different programs can exchange it without sharing the same internal data model.

<course code="WT205">
    <title>Web Technologies</title>
    <credits>4</credits>
    <instructor>Dr. Mehta</instructor>
</course>

Extensible

Authors choose meaningful element and attribute names for their domain; XML itself does not prescribe a fixed vocabulary.

Structured

Elements nest in a tree, allowing records to contain related subrecords in a clear parent-child relationship.

Portable text

XML can be read by people and processed by software on different platforms. It is a data format, not a programming language.

XML is not HTML. HTML has standard elements with browser-defined meaning and presentation. XML allows custom names and focuses on carrying data; it does not automatically create a styled user interface.

Well-formed versus valid

A well-formed XML document follows XML syntax rules: it has one root element, tags are properly nested and closed, and attribute values are quoted. A valid document is well-formed and also conforms to a declared grammar such as a DTD or XML Schema (XSD). A browser's XML parser can check basic well-formedness, but it does not automatically validate against every DTD or XSD.

The demo uses the browser's DOMParser and reports the number of book elements.

Where XML is used

  • Exchanging structured data between applications and services.
  • Configuration files, document formats, and feeds such as RSS.
  • Representing data where explicit structure and human readability matter.

02XML Key Components

An XML document is a tree of nodes. The following example includes the most common pieces: a declaration, a root element, nested elements, attributes, text, and a comment.

<?xml version="1.0" encoding="UTF-8"?>
<student id="s-204" status="active">
    <name>Mira Shah</name>
    <programme>B.Tech CSE</programme>
    <marks subject="XML">88</marks>
    <!-- A student record -->
</student>

XML syntax rules to remember

  • Element names are case-sensitive: <Name> and <name> are different names.
  • Every opened element must be closed, or be empty-element syntax such as <image/>.
  • Elements must be properly nested; <b><i>...</b></i> is not well-formed.
  • There must be exactly one document element (root), though it may contain many children.
  • Reserved characters in text must be escaped: use &amp;, &lt;, and &gt; for ampersand, less-than, and greater-than.

Namespaces

Namespaces prevent naming collisions when XML from different vocabularies is combined. A namespace prefix is connected to a URI by xmlns; the URI identifies the vocabulary and does not have to be a working web page.

<course xmlns:lib="https://example.edu/library">
    <title>Web Technologies</title>
    <lib:title>XML for Libraries</lib:title>
</course>

Here, the unprefixed title and lib:title are distinct names because the latter belongs to the library namespace.

03DTD and Schemas

Well-formedness checks syntax, but it does not specify which elements a particular application expects. A grammar defines allowed elements, attributes, their order, and how often they may appear. XML processors can use that grammar to validate a document before the application consumes it.

DTD (Document Type Definition)

A compact grammar that declares elements, attributes, entities, and content models. A DTD can be embedded in an XML document or stored as an external .dtd file. DTD syntax is not itself XML and has limited data typing.

XML Schema (XSD)

An XML-based grammar that supports built-in types such as xs:decimal, constraints, namespaces, and reusable type definitions. XSD is more expressive and strongly typed than DTD.

One catalog, described by a DTD

Save the following as catalog.dtd. It requires one or more product elements, each with a name followed by a price; every product must have an id attribute.

<!ELEMENT catalog (product+)>
<!ELEMENT product (name, price)>
<!ATTLIST product id ID #REQUIRED>
<!ELEMENT name (#PCDATA)>
<!ELEMENT price (#PCDATA)>

Save this matching instance as catalog.xml. The document type declaration connects it to the external DTD.

<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE catalog SYSTEM "catalog.dtd">
<catalog>
    <product id="p101">
        <name>Notebook</name>
        <price>45.50</price>
    </product>
    <product id="p102">
        <name>Pen set</name>
        <price>30.00</price>
    </product>
</catalog>

Describe the same structure with XML Schema

Save the following as catalog.xsd. The schema requires a decimal price and a product ID, and enforces the order of child elements.

<?xml version="1.0" encoding="UTF-8"?>
<xs:schema xmlns:xs="http://www.w3.org/2001/XMLSchema">
    <xs:element name="catalog">
        <xs:complexType>
            <xs:sequence>
                <xs:element name="product" maxOccurs="unbounded">
                    <xs:complexType>
                        <xs:sequence>
                            <xs:element name="name" type="xs:string"/>
                            <xs:element name="price" type="xs:decimal"/>
                        </xs:sequence>
                        <xs:attribute name="id" type="xs:ID" use="required"/>
                    </xs:complexType>
                </xs:element>
            </xs:sequence>
        </xs:complexType>
    </xs:element>
</xs:schema>

For XSD validation, use this XML header instead of the DTD declaration above. Keep the catalog body the same.

<?xml version="1.0" encoding="UTF-8"?>
<catalog xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:noNamespaceSchemaLocation="catalog.xsd">
    ...
</catalog>
Run the validation examples: Save the DTD version as catalog.xml beside catalog.dtd, then run xmllint --noout --valid catalog.xml. To validate with XSD, replace the DTD declaration with the schema header and run xmllint --noout --schema catalog.xsd catalog.xml. These commands use the xmllint utility (provided by libxml2); a successful validation reports that the document validates.

04Transforming XML using XSL and XSLT

XSL (Extensible Stylesheet Language) is a family of technologies for working with XML. Its key parts include XSLT (rules for transforming XML), XPath (expressions for selecting nodes and values), and XSL-FO (formatting objects, commonly used for paginated output). In many introductory materials, “XSL” is used informally to mean an XSLT stylesheet.

XSLT reads a source XML tree, selects nodes with XPath, and applies template rules to produce a result. The result can be HTML for a web page, another XML vocabulary, or plain text. XSLT changes the representation of data; it does not change the source XML.

Transformed HTML result
Press “Transform XML” to create the table.

What the stylesheet does

  • <xsl:template match="/"> begins at the document root.
  • <xsl:for-each select="catalog/book"> selects each book with an XPath expression and repeats the enclosed output.
  • <xsl:value-of select="@id"/> reads an attribute; selecting title or author reads an element's text.
  • Literal HTML tags such as <table> become part of the result document.

Connect an XML file to a stylesheet

For a standalone XML file, an xml-stylesheet processing instruction can associate it with an XSLT file. Save the XML and XSLT files together and open the XML in a browser that supports this instruction.

<?xml version="1.0" encoding="UTF-8"?>
<?xml-stylesheet type="text/xsl" href="catalog.xsl"?>
<catalog>
    <book id="b101">
        <title>Learning XML</title>
        <author>Asha Rao</author>
        <price>450</price>
    </book>
</catalog>

For a command-line demonstration, save the source as catalog.xml and the stylesheet from the workbench as catalog.xsl, then run xsltproc catalog.xsl catalog.xml. The transformed HTML is written to standard output; xsltproc is available with libxslt.

Compatibility: The interactive example uses XSLT 1.0 through the browser's XSLTProcessor API. It works in browsers that still expose that API, but Chromium currently warns that XSLT support is deprecated and may remove it. Use the xsltproc command for a durable local demonstration. Newer XSLT versions and server-side transformations require an appropriate processor; browser support is not a substitute for server-side validation.

Unit 5 at a glance

  1. XML is an extensible, text-based format that describes structured data.
  2. Elements, attributes, text, and namespaces make up the document tree; well-formedness is the baseline syntax requirement.
  3. DTD and XSD declare allowed document structure. XSD adds richer types and constraints.
  4. XSLT uses XPath and template rules to transform XML into HTML, XML, or text.
